BeME architecture note

ラティスは、
「位置」と「単語」の地図。

BeMEがIPADICから何を残し、何を捨てたのか。まずグラフの形を正しく持ってから、単語生起コストと接続コストがDPでどう足されるかを追います。

01

最初の要点： BeMEコードでは入力中の位置がnode、辞書から見つかった単語候補がedgeです。ただしMeCabの文献では、単語候補そのものをnodeと呼ぶことがあります。

05 / DP STATE

なぜ状態に「直前POS」が要るのか

未来のコストは現在位置だけでは決まりません。次の単語へ接続するとき、直前の単語が何だったかを覚えておく必要があります。

DPの状態

state = (position, previous_pos)

同じ位置2に到達していても、直前が verb の経路と noun の経路では、次の候補への接続コストが違います。

本来のIPADICを再現するなら、ここで必要なのは粗いPOSではなく、直前単語の right_id です。

# 経路を単語候補edgeで1本伸ばす
cost = (
    path.cost
    + edge.token.cost
    + pos_transition_cost(
        previous_pos,
        edge.token.pos,
      )
)

06 / FORMAL

グラフ理論の言葉だけで定義する

BeMEのラティスは、辺に単項コストを持ち、連続する辺のペアに二項コストを持つ、有向多重DAGです。

グラフと候補パス

G = (V, E),   V = {0, 1, 2, 3}
e₁=(0,2)単語候補「受け」
e₂=(2,3)単語候補「て」
e₃=(0,3)単語候補「受け手」
Psplit = (e₁, e₂)
Psingle = (e₃)

変換とは、始点0から終点3までのパスのうち、総コストが最小のものを選ぶことです。

パスの目的関数

生起コストは1本の辺に対する関数、接続コストは連続する2辺に対する関数です。

w : E → ℝ
c : E × E → ℝ
C(P) = ∑i=1k w(ei) + ∑i=1k−1 c(ei, ei+1)
C(Psplit) = 3.968 + 0.050 + 2.835 = 6.853
C(Psingle) = 3.085

通常の最短経路問題へ変換する

元グラフでは接続コストが「辺のペア」に依存します。元の各辺を新しい頂点にする状態展開を行えば、通常の重み付きグラフとして扱えます。

元の位置グラフ
0─ 受け →2─ て →3
0── 受け手 ──→3
→
辺を頂点にした状態展開グラフ
S→受け→て→T
S→受け手→T
w(e)元グラフの各辺に載る単語生起コスト
c(e,f)状態展開後の頂点e→fを結ぶ弧に載る接続コスト

結論： 生起コストは edge weight、接続コストは edge-transition cost です。後者があるため、DP状態は位置だけでなく直前の辺に関する情報も必要です。BeMEでは接続コストがPOSだけに依存するので、直前辺を previous_pos へ圧縮しています。

One sentence summary

単語候補edgeの値は残した。edgeから次のedgeへ移る採点器を、粗い手作り版に置き換えた。

残した

表層、読み、粗いPOS、変換済みの単語生起コスト

捨てた

left_id、right_id、matrix.defが持つ詳細な接続信号

代わりに使う

直前POSと現在POSから引く、小さな手書き固定コスト
