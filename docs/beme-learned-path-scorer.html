1. 前提：いまはパラメータ調整の段階ではない

現在のBeMEは、複数の手作りルールを足し合わせて経路を採点しています。

IPADIC由来の生起コスト
+ 16 POSの手書き接続コスト
+ 手作りoverlay
+ カタカナ表層ペナルティ
+ 個別の補正

この目的関数を固定したまま値だけを調整すると、補正同士が依存し始めます。

接続報酬が弱い
  ↓
助詞の生起コストをoverlayで安くする
  ↓
一文字語が強くなりすぎる
  ↓
別のペナルティを追加する

改善できたとしても、「なぜその値なのか」「別の評価セットでも効くのか」を説明しにくくなります。

設計判断： 現行モデルを固定してマジックナンバーを増やすのではなく、正解経路と誤り経路の差から採点関数を学習できる構造へ移行する。

2. 残すものと置き換えるもの

残すもの

ラティスとDPは、読みから表記を選ぶ問題に自然に適合しています。

入力位置を頂点にする
辞書候補をedgeにする
始点から終点までの最小コスト経路を探す
K-best経路を列挙する

置き換えるもの

置き換えるべきなのは、ラティスではなく採点器です。

map_ipadic_cost()
_TRANSITION_COSTS
overlayの絶対的な低コスト
カタカナ +1.0

これらを独立した規則として積み重ねる代わりに、経路から特徴量を抽出し、その重みをデータから学習します。

3. 「辞書学習」ではなく「経路学習」にする

パス P のコストを、特徴量の線形結合として定義します。

Cθ(P) = θTΦ(P)
  • Φ(P)：経路から抽出した特徴量
  • θ：訓練データから学習する重み

単語edgeの特徴と、隣接edge間の特徴に分けると、

Cθ(P) = ∑e∈P θlexTφ(e) + ∑(e,f)∈P θtransTψ(e,f)

となります。

現在のモデルは、φ(e) がほぼIPADIC生起コストだけ、ψ(e,f) が16 POSの手書き表だけ、という特殊ケースとみなせます。

4. 何を特徴量にするか

単語edgeの特徴量

種類例狙い
辞書属性reading、surface、POS、詳細POS語彙と品詞の違いを表現
接続属性left_id、right_id、活用形粗いPOSで失った接続状態を復元
形状読み長、表層長、漢字・かな・カタカナ長語、無変換、カタカナ漏れを制御
頻度コーパス頻度、読み内の表記頻度IMEとして一般的な表記を優先
出所IPADIC、overlay、追加辞書、未知語候補生成元ごとの信頼度を学習
既存値IPADIC word cost既存知識を初期特徴として利用

edge間の特徴量

  • 前POS → 現POS
  • 前right_id → 現left_id
  • 前の活用形 → 現在の品詞
  • 前の表層末尾 → 現在の表層先頭
  • 単語長・読み長の組み合わせ
  • IPADIC matrix cost

特徴量として保持することと、その値を目的関数として無条件に信頼することは別です。IPADICの値も、学習器が重みを決める入力の一つへ下げます。

5. 最初の学習器にはstructured perceptronが合う

最初から巨大なニューラルモデルにする必要はありません。現在のViterbi探索をそのまま利用できるstructured perceptronが、最初の学習器として実装しやすい選択です。

各訓練例について、次を繰り返します。

  1. 現在の重みで1-best経路を求める
  2. 正解表記を生成する経路をラティスから探す
  3. 正解経路と予測経路の特徴量差で重みを更新する
θ←θ+η ( Φ(Pgold) − Φ(Ppred) )

例えば、

正解:  受け + て
予測:  受け手

なら、学習によって次の方向へ重みが動きます。

  • 「動詞連用形 → 接続助詞」の特徴を有利にする
  • 「受け」「て」の語彙特徴を有利にする
  • この文脈で「受け手」を選んだ特徴を不利にする

人間が ("verb", "particle"): -1.0 のような値を決める必要がなくなります。

6. 正解経路をどう決めるか

正解表記が与えられても、正解の形態素分割が与えられるとは限りません。

入力読み: にんむではかれからむせんでしじをうけて
正解表記: 任務では彼から無線で指示を受けて

そこで、オラクル分析と同じ制約付きDPを利用します。

状態 = 入力読み位置
     × 正解表記位置
     × 直前の接続状態

正解表記を生成する経路が複数ある場合は、現在のモデルで最もスコアが良い正解経路を選びます。

Pgold = argminP:surface(P)=target Cθ(P)

正解表記を作る経路が存在しない場合は学習スコアの問題ではなく、候補生成・辞書coverageの問題として別に記録します。

7. 訓練データをどう作るか

日本語本文コーパスから、読みと正解表記のペアを合成できます。

元の本文:
  彼から無線で指示を受けて

形態素解析から読みを生成:
  かれからむせんでしじをうけて

訓練ペア:
  input  = かれからむせんでしじをうけて
  target = 彼から無線で指示を受けて

読み生成にMeCabを使うと解析器のバイアスは入ります。それでも、単語の絶対頻度を数えるだけの学習より、読みから正解文を生成するIMEの目的に近くなります。

学習目的の変更： 「頻出単語を安くする」から、「正解文を生成する経路を誤変換経路より安くする」へ。

データは必ずtrain・development・testへ分割し、ハイパーパラメータ選択と最終評価を分離します。AJIMEE、Mozc、handmadeは分布の異なる回帰検出として併用します。

8. IPADICは「正解」ではなく特徴量の一つにする

IPADICの情報を捨てる必要はありません。しかし、形態素解析向け目的関数をIMEへ忠実に移植する必要もありません。

C(e,f) = θ1CIPADIC-word(f) + θ2Cmatrix(e,f) + θ3I[katakana] + θ4logfreq(f) +…

学習結果として、例えば次のようなバランスを獲得できます。

IPADIC生起コスト      弱めに利用
matrix接続コスト      0.2倍程度で利用
カタカナ表層         少し不利
読み条件付き頻度     強く利用
overlay              出所特徴として利用

matrix.defを使うか捨てるかの二択ではなくなります。

9. ニューラルモデルはその次に置く

候補生成
  辞書・数字・未知語・固有名詞
        ↓
局所的な経路スコア
  学習済み生起特徴 + 学習済み接続特徴
        ↓
文全体のリランク
  Transformer / Cross-Encoder / 言語モデル

局所モデルはDP可能な形を維持し、正解を含む質の良いK-bestを生成します。その後、局所接続だけでは解けない表記を文全体のモデルで選びます。

鳴る / 成る
挙げる / 上げる
復讐 / 復習
制作 / 政策

最初からend-to-endのseq2seqへ移る選択肢もありますが、失敗箇所の説明、辞書制約、固有名詞制御、必要データ量の面で代償があります。現在のBeMEなら、まず学習可能なラティススコアラーへ進む方が、既存資産を活かしながら抜本的に変えられます。

10. 実装ロードマップ

  1. 現行baselineを固定する
    評価設定、辞書リビジョン、AJIMEE・Mozc・handmadeの結果を再現可能にする。
  2. 辞書スキーマを拡張する
    詳細POS、活用形、left/right ID、辞書出所、元コストを保持する。
  3. 採点器を分離する
    FeatureExtractorとLinearScorerを導入し、探索実装からコスト定義を切り離す。
  4. 正解表記制約付きオラクルDPを実装する
    正解文字列を生成する経路を訓練時に取得できるようにする。
  5. structured perceptronを実装する
    正解経路と予測経路の特徴量差から重みを更新する。
  6. train / development / testを分離する
    学習、ハイパーパラメータ選択、最終評価を混ぜない。
  7. 候補coverageを改善する
    数字、未知語、カタカナ語、固有名詞について正解経路が存在する割合を上げる。
  8. 最後に文脈リランカを学習する
    oracle recallが十分になってから、文全体の意味でK-bestを並べ替える。
最終方針： ラティス探索は残す。現在の手作りコストモデルは固定せず、正解経路と誤り経路の差から学習する。既存の辞書コスト学習PoCは、この方向へ進むための最初の証拠として位置づける。
