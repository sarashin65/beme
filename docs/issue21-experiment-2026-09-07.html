結論: 疎な語彙重みは汎用特徴として A8 比 -29.2% の改善（S0）を示したが、F2（-40.6%）には及ばず、F2 と冗長（S1 = C0 と同等）。理論上限分析（Opus 実測）により汎用特徴としての撤退基準を確認。

→ issue #21 を 「デバイス端の個人適応（ユーザー語彙学習）」として再定義。既存基盤はそのまま再利用する。

1. 経緯 — 符号バグの発見と修正

⚠️ 最初の実験は符号バグで失敗
`_update_sparse_weights` が正解トークンに +lr を加算していた。`edge_cost` はコスト（Viterbi は最小化）なので、正解トークンは -lr すべきだった。

結果: 疎重みが max 280 まで暴走し、S0 = 789（A8 より +52% 悪化）· 訓練誤差が epoch ごとに増加。

符号バグの 4 つの証拠（Opus 実測）

  1. 学習後重みの意味的逆転: 「の/の」= +183.5（最コスト高 = 避ける）·「の/之」= -178.8（最コスト低 = 選ぶ）→ モデルが「異体字を書け」と学習していた
  2. 訓練誤差の単調増加: 3377 → 3530（epoch ごとに悪化）
  3. 更新回数が A8 の 5.6 倍（収束せず暴走）
  4. 6行の最小再現コードで確認

修正内容（コミット fe7bb0f）

  • 符号反転: gold = -lr / pred = +lr
  • surface 層削除（pair 単層に。Opus が情報量ゼロを実証: surface ≡ Σ_r pair[r,s]）
  • load() の suffix 判定バグ修正
  • テストに挙動アサーション追加（符号方向の回帰防止）

3. 解釈

3.1 疎重みは単体で有効、でも F2 と冗長

  • S0（-29.2%）: 疎重み単体でも大きく改善。学習データ由来の語彙知識が効いている
  • S1 ≈ C0（312 vs 309）: F2 に疎重みを足しても改善なし → 同じ信号源（学習データの語彙知識）で F2 の方が強い

3.2 理論上限（Opus 実測）

完全記憶オラクル（全ペアを覚えた理想器）でも:
  C0 上: 309 → 291（-5.8%・McNemar p = 0.13 → 有意差なし）
  train を 1,250 → 10,000 に増やしても改善は横ばい

汎用特徴としての撤退基準は満たされた（312 vs 309 で p < 0.05 未達）。

4. 方向転換: デバイス端の個人適応へ

汎用特徴としては撤退するが、基盤はそのまま再利用して「個人適応」へ転用する。

汎用特徴（撤退）個人適応（新方向）

F2 との関係冗長（同じ信号）相補的（F2 は原理的にカバー不能）
