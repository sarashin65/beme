BeMEのラティスをグラフ理論で理解する

入力位置、単語候補、生起コスト、接続コストを、グラフ理論の用語だけで整理する。

目次
  1. グラフの定義
  2. 生起コストは辺の重み
  3. 接続コストは「辺のペア」のコスト
  4. 普通の最短経路問題と何が違うのか
  5. 普通の重み付きグラフに変換する方法
  6. BeMEのDP状態
  7. なぜ previousEdge を previousPOS に圧縮できるのか

1. グラフの定義

グラフ理論として厳密に言うと、BeMEのラティスは単純な「重み付き有向グラフ」ではなく、連続する2本の辺にもコストを持つ有向多重DAGです。

入力が「うけて」で、文字位置が 0, 1, 2, 3 なら、

V={0,1,2,3}

が頂点集合です。

単語候補を辺として、

E⊆V×V

を作ります。

具体的には、

e₁ = (0, 2, 受け)
e₂ = (2, 3, て)
e₃ = (0, 3, 受け手)

です。同じ始点・終点を持つ別表記候補も存在できるので、正確には有向多重グラフです。

0 ── e₁:受け ──> 2 ── e₂:て ──> 3
│
└──────── e₃:受け手 ─────────> 3

変換とは、頂点 0 から頂点 3 までのパスを一つ選ぶことです。

候補パスは、

P1=(e1,e2)

と、

P2=(e3)

です。

2. 生起コストは辺の重み

各単語候補辺 e に、単項コスト w(e) があります。

w:E→ℝ

これが生起コストです。

w(e₁) = w(受け)   = 3.968
w(e₂) = w(て)     = 2.835
w(e₃) = w(受け手) = 3.085

ここまでは普通の重み付きグラフです。

3. 接続コストは「辺のペア」のコスト

接続コストは頂点の重みでも、単独の辺の重みでもありません。

連続可能な2辺、

e=(i,j), f=(j,k)

に対する二項コストです。

c:E×E→ℝ

ただし、

head(e)=tail(f)

を満たす場合だけ定義されます。

今回なら、

c(e1,e2) =c(受け,て) =0.05

です。したがって、パス

P=(e1,e2,…,ek)

の総コストは、

C(P)= ∑i=1k w(ei) + ∑i=1k−1 c(ei,ei+1)

になります。

「受け＋て」なら、

C(P1)= w(e1)+ c(e1,e2)+ w(e2)
=3.968+0.05+2.835=6.853

「受け手」なら辺が1本なので、辺ペアがありません。

C(P2)=w(e3)=3.085

したがって、

C(P2)<C(P1)

なので「受け手」が選ばれます。

4. 普通の最短経路問題と何が違うのか

普通の最短経路問題は、

C(P)=∑e∈Pw(e)

のように、各辺の重みを足すだけです。

しかしBeMEは、

C(P)= ∑w(ei) + ∑c(ei,ei+1)

なので、次の辺のコストが「直前にどの辺を通ったか」に依存します。

つまり、元の位置グラフ上では一次のマルコフ性を持つ辺遷移コスト付き最短経路問題です。

位置 2 に到達しただけでは、次のコストを決められません。

どの辺を通って位置2に来たか

も状態に必要です。

5. 普通の重み付きグラフに変換する方法

これを通常の最短経路問題にしたければ、元のグラフの「辺」を新しいグラフの「頂点」にします。

これは線グラフに近い状態展開です。

元のグラフ

位置0 ──受け──> 位置2 ──て──> 位置3
位置0 ─────────受け手────────> 位置3

状態展開後

START ──> [受け] ──> [て] ──> END
   │
   └────> [受け手] ─────────> END

新しいグラフでは、

  • 頂点 [受け] に生起コスト 3.968
  • 頂点 [て] に生起コスト 2.835
  • 弧 [受け] → [て] に接続コスト 0.05

を置けます。

頂点重みを入辺へ移せば、完全に普通の辺重み付き最短経路問題になります。

START → [受け]   : 3.968
[受け] → [て]    : 0.05 + 2.835
[て] → END       : 0

とすれば、総コストは同じです。

6. BeMEのDP状態

厳密には直前の辺全体を保持すれば、

DP[position,previousEdge]

です。

ただしBeMEの接続コストは、辺のPOSしか見ません。

c(e,f)= T(pos(e),pos(f))

そのため、同じPOSの辺を同一状態へまとめられます。

DP[position,previousPOS]

実装の、

remaining[position][previous_pos]

はこれです。

MeCabの本来の接続コストなら、

c(e,f)= M[rightId(e)] [leftId(f)]

なので、DP状態は少なくとも、

DP[position,previousRightId]

になります。

7. なぜ previousEdge を previousPOS に圧縮できるのか

理由は、previousEdge が持つ情報のうち、未来のコスト計算に使われるのが previousPOS だけだからです。

これはDPにおける「十分な状態」への圧縮です。

元の状態

厳密に書くと、位置 p 以降の最小コストは、

F(p,eprev)

です。次の単語候補edgeを f とすると、

F(p,eprev) = minf [ c(eprev,f) +w(f) +F(end(f),f) ]

となります。

  • w(f)：次の単語の生起コスト
  • c(eprev,f)：直前edgeと次edgeの接続コスト

BeMEの接続コストが見るのはPOSだけ

BeMEでは、接続コストを次のように計算しています。

c(e,f) = T(pos(e),pos(f))

つまり、直前edgeについて参照するのは、表層、読み、開始位置、生起コストではなく、e.pos だけです。

例えば、同じ位置に次の2経路で到着したとします。

経路A → 「本」 noun → position=5
経路B → 「人」 noun → position=5

直前edgeは「本」と「人」で異なります。しかし、どちらも直前POSは noun です。次のedgeが「を」なら、BeMEが見る接続コストはどちらも、

pos_transition_cost("noun", "particle")

です。このモデルには「本」と「人」を区別する材料がありません。

安い部分経路だけ残せる理由

位置と直前POSが同じ2つの部分経路を考えます。

経路A:
  累積コスト    = 10.0
  position      = 5
  previousPOS   = noun

経路B:
  累積コスト    = 12.0
  position      = 5
  previousPOS   = noun

今後どの続きを選んでも、追加される未来コストは両者で同じです。未来コストが 7.0 なら、

経路Aの最終コスト = 10.0 + 7.0 = 17.0
経路Bの最終コスト = 12.0 + 7.0 = 19.0

別の続きを選び、未来コストが 9.0 になっても、

経路Aの最終コスト = 10.0 + 9.0 = 19.0
経路Bの最終コスト = 12.0 + 9.0 = 21.0

です。経路Bが後から逆転することはありません。

Bellmanの最適性原理： 同じ状態に到着した部分経路のうち、コストが高い方は、その後どの共通の続きを選んでも最適解になれません。

圧縮後のDP漸化式

状態を、

DP[p,q]

とします。

  • p：現在の入力位置
  • q：直前に選んだ単語のPOS

現在位置 p から単語候補edge f=(p,j) を選び、そのPOSを r とすると、

DP[j,r] = min( DP[j,r], DP[p,q] +T(q,r) +w(f) ) 
for previous_pos in possible_previous_pos:
    for edge in outgoing_edges[position]:
        current_pos = edge.token.pos

        new_cost = (
            dp[position][previous_pos]
            + pos_transition_cost(previous_pos, current_pos)
            + edge.token.cost
        )

        dp[edge.end][current_pos] = min(
            dp[edge.end][current_pos],
            new_cost,
        )

次の接続コスト計算で必要なのは、今回選んだedgeのPOSだけです。そのため、次の状態にはedge全体ではなく current_pos だけを渡せます。

なぜ DP[position] だけでは足りないのか

POSまで捨てて、

DP[position]

だけにすることはできません。同じ位置に到達していても、直前POSが noun か verb かによって、次の単語への接続コストが異なるからです。

T("noun", "particle")
T("verb", "particle")

つまり、

previousEdge は情報が多すぎる
position だけでは情報が足りない
previousPOS がBeMEでは必要十分

ということです。

MeCabでは previousRightId に圧縮できる

MeCabの接続コストは、

c(e,f) = M[rightId(e)] [leftId(f)]

です。未来の接続計算で直前edgeから必要なのは right_id だけなので、MeCab相当のDPなら、

DP[position,previousRightId]

まで圧縮できます。

new_cost = (
    dp[position][previous_right_id]
    + matrix[previous_right_id][edge.left_id]
    + edge.word_cost
)

dp[edge.end][edge.right_id] = min(
    dp[edge.end][edge.right_id],
    new_cost,
)

同じ verb でも right_id が異なれば、MeCabでは次の語への接続コストが異なるので、別状態として扱います。BeMEはそれらをすべて previousPOS=verb に統合しています。

一般化

DPの状態に残すべきなのは、過去を完全に記録する情報ではなく、未来のコストを決めるために必要な最小限の情報です。

過去のedge列
    ↓ 圧縮
直前edge
    ↓ さらに圧縮
直前POS

この圧縮が成立する条件は、

c(e,f) = T(pos(e),pos(f))

であり、未来のコストがそれ以前の履歴を参照しないことです。もし接続モデルが直前の表層、直前2単語、文頭からの全文脈を見るなら、previousPOS だけにはまとめられません。

要点： 同じ位置・同じ直前POSに到達した経路は、BeMEのコストモデルから見ると未来に対して区別不能なので、同じDP状態へまとめられます。

一番重要な整理はこれです。

位置                         = 頂点
単語候補                     = 辺
生起コスト w(e)              = 1本の辺に対する単項コスト
接続コスト c(e,f)            = 連続する2本の辺に対する二項コスト
変換                         = 始点から終点への最小コストパス

つまり接続コストとは、グラフ理論的には「edgeのコスト」ではなく、edge transition costです。
