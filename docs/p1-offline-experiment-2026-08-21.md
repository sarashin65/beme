# P1（matrix.def 取り込み）オフライン実験 — 2026-08-21

## 結論

**AJIMEE の CER 改善を目的とする限り、P1 を「IPADIC の生起コスト + `matrix.def` へそのまま切り替える」仕様で実装する価値は、今回の実測では確認できなかった。**

- A（現行 BeME）: mean CER **0.341433**、完全一致 **12/200 = 6.0%**
- B（IPADIC 生起コスト + 接続コスト）: mean CER **0.344480**、完全一致 **13/200 = 6.5%**
- CER は B で **+0.003047（相対 +0.89%、悪化）**。完全一致は 1 件純増した。
- ケース単位では **改善 81 / 悪化 69 / 同点 50**。改善件数は多いが、悪化側の平均変化量が大きく、mean CER は悪化した。
- mean edit distance は **6.560 → 6.295** と改善した。短い正解文での大きな悪化が mean CER を押し上げている。

`docs/deepdive-2026-08-21.md` §5 の **CER 0.15〜0.22 という期待値は実測で支持されなかった**。接続行列は §2.1 の一部の分割誤りを大きく直す一方、IPADIC が形態素解析辞書であり IME の表記選択モデルではないため、別のケースを同程度以上に壊した。

したがって、**提案どおりの P1 は AJIMEE 品質施策としては見送り、目的関数を再設計してから再実験するのが妥当**である。`matrix.def` の忠実な再現自体に保守性・説明可能性上の価値はありうるが、それは CER 改善とは別の判断軸である。

## 実験条件

### 共通条件

- 対象: `data/ajimee_bench_jwtd_v2_v1.json` の全 200 件
- 辞書・候補空間: 両系とも `data/dictionary.tsv`
- ラティス: 両系とも `beme.lattice.build_lattice` が作る同じ読み位置 DAG
- `beam_width=64`
- `top_k=1`
- AJIMEE のカタカナ→ひらがな正規化、非かな文字でのスパン分割、スパンごとの状態リセットは `beme.benchmark.convert_sentence` と同じ
- 複数正解があるケースの CER は、現行評価と同じく各正解に対する CER の最小値

### A: 現行 BeME

リポジトリの `Converter` / `k_best_viterbi` をそのまま使用した。

$$
C_A = \sum_i C_{\text{BeME lexical}}(i) + \sum_i C_{\text{16-POS transition}}(i-1,i)
$$

各ケースで独自に採取した A の出力・コストが `convert_sentence(..., k=1)` の出力・コストと一致することを実験スクリプト内で検査した。集計値は既報の baseline（CER 0.341433 / exact 6.0%）とも一致した。

### B: IPADIC 目的関数

IPADIC 原本 `/tmp/mecab-ipadic_2.7.0-20070801+main.orig.tar.gz` の CSV と `matrix.def`（1316×1316）を直接読み、各ラティス辺を次で採点した。

$$
C_B = \sum_i C_{\text{IPADIC word}}(i)
    + C_{\text{matrix}}(\mathrm{BOS},i_1)
    + \sum_{i>1} C_{\text{matrix}}(i_{i-1}.right,i_i.left)
    + C_{\text{matrix}}(i_n,\mathrm{EOS})
$$

- IPADIC 由来の 349,017 辺は、`beme.ipadic._load_imported_entries` と同じファイル順・重複排除規則を再現し、生起コストと left/right ID を復元した。
- これにより、現行 TSV で同一 `(reading, surface, pos)` に潰れたレコードも、現行辞書ビルドが実際に残した 1 レコードへ決定的に対応した。
- 既報 §2.1 の検算値を再現した:
  - `を受けて`: **14401**（word 16789 + connection −2388）
  - `を受け手`: **8538**（word 9852 + connection −1314）
- 現行辞書にだけ存在する overlay 26 辺のうち、21 辺は同じ reading/surface を生成する IPADIC 形態素列へ展開し、その内部生起・接続コストと外側 left/right ID で「マクロ辺」として採点した。見える reading/surface 候補は増減していない。
- 残る 5 辺は IPADIC に同じ reading/surface を生成する経路がないため、主実験では `unk.def` の最安 HIRAGANA 名詞（left=right=1285、word=13069）を代理値にした。ただし **B の選択結果でこの代理辺が採用されたケースは 0 件**。word=100000 として実質無効化しても全 200 件の B 出力・指標は完全に同一だった。
- 通常の一文字未知語辺も同じ HIRAGANA 未知語コストで採点した。

ここで「同じ候補空間」は、reading/surface のラティス辺が同一という意味である。overlay マクロ辺の内部には IPADIC ID 列を持たせたが、新しい reading/surface 出力は追加していない。

## 集計結果

| 指標 | A: 現行 BeME | B: IPADIC word + matrix | B − A |
|---|---:|---:|---:|
| mean CER | **0.341433** | **0.344480** | **+0.003047** |
| 完全一致 | 12/200（6.0%） | 13/200（6.5%） | +1 件（+0.5 pt） |
| mean edit distance | 6.560 | 6.295 | −0.265 |

| CER 比較 | 件数 |
|---|---:|
| B が改善 | **81** |
| B が悪化 | **69** |
| 同点 | **50** |

追加観測:

- A と B の出力文字列が完全に同じなのは 17/200 件。目的関数の切り替えは 183 件の 1-best を変えた。
- 改善 81 件の CER 改善量合計は 13.1161（平均 0.1619/件）。悪化 69 件の悪化量合計は 13.7254（平均 0.1989/件）。
- 完全一致の遷移は「A のみ正解」6 件、「B のみ正解」7 件、「両方正解」6 件。
- B が採用した辺は IPADIC native 2,319、通常の HIRAGANA unknown 10、overlay マクロ 30（28 ケース）、unsupported-overlay 代理辺 0。

## 大きく改善した代表例

コスト表の表記:

- `current A-path`: A 出力を現行目的関数で採点
- `current B-path`: B 出力を現行目的関数で交差採点
- `IPADIC A-path`: A 出力を B の目的関数で交差採点
- `IPADIC B-path`: B 出力を B の目的関数で採点
- 現行コストは `lexical + connection = total`、IPADIC コストは `word + connection = total`
- 句読点で分かれたスパンは BOS/EOS を個別に含み、表の値は文内スパンの合計

### 1. `ajimee-jwtd-v2-2108` — CER 0.8182 → 0.2727（−0.5455）

- 正解: `を履いて単気筒エンジン`
- A: `をは射手短気と迂遠人`
- B: `を佩いて短気灯エンジン`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 10.467 + 0.350 = **10.817** | 15.625 + 0.360 = 15.985 |
| IPADIC | 38143 − 9158 = 28985 | 32232 − 15815 = **16417** |

B の主経路は `を → 佩い → て → 短気 → 灯 → エンジン`。特に `佩い→て` の接続が −7392、`を→佩い` が −3934 と強く、現行の `を→は→射手...` を逆転した。`履い/佩い` の表記選択はなお誤るため完全一致にはならない。

### 2. `ajimee-jwtd-v2-305` — CER 1.0000 → 0.5556（−0.4444）

- 正解例: `堅い殻を持つ卵を産むこと、高い代謝率`
- A: `か大からを持つタマゴを有無コト、タカイ大車リツ`
- B: `加タイカラを持つタマゴを産むコト、高い代謝率`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 20.356 + 0.920 = **21.276** | 29.830 + 0.860 = 30.690 |
| IPADIC | 83607 − 14061 = 69546 | 61627 − 40691 = **20936** |

B は後半を `高い → 代謝 → 率` と切り、`産む` も選べた。主要接続は `を→産む` −4081、`産む→コト` −4260、`代謝→率` −5447。§2.1 の「接続コストが分割を直す」仮説が実際に働いた例である。ただし先頭は `加タイカラ`、`卵/こと` はカタカナのままで、IPADIC だけでは表記品質が残る。

### 3. `ajimee-jwtd-v2-965` — CER 0.4167 → 0.0000（完全一致）

- 正解: `外部の歌手の楽曲制作では`
- A: `がイブの歌手の楽曲政策では`
- B: `外部の歌手の楽曲制作では`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 12.072 + 0.400 = **12.472** | 12.688 + 0.370 = 13.058 |
| IPADIC | 41491 − 20227 = 21264 | 39555 − 20608 = **18947** |

B の経路は `外部 → の → 歌手 → の → 楽曲 → 制作 → で → は`。`外部→の` −4442、`歌手→の` −4442、`制作→で` −4675 など、名詞・サ変名詞から機能語への接続報酬が正しい分割を支えた。

### 4. `ajimee-jwtd-v2-1859` — CER 0.4000 → 0.0000（完全一致）

- 正解: `の自社制作`
- A: `の自社政策`
- B: `の自社制作`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 4.479 + 0.150 = **4.629** | 4.515 + 0.150 = 4.665 |
| IPADIC | 11764 − 1986 = 9778 | 11835 − 2476 = **9359** |

生起コスト合計だけでは B 側が 71 高いが、接続コストが 490 低く、`政策` ではなく `制作` を選んだ。小さいが明確な matrix 起因の逆転である。

### 5. `ajimee-jwtd-v2-1936` — CER 0.6000 → 0.2000（−0.4000）

- 正解例: `可哀想な思いをさせた`
- A: `可愛双な重いを佐セタ`
- B: `可哀想な思いをさセタ`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 12.734 + 0.430 = **13.164** | 17.028 + 0.450 = 17.478 |
| IPADIC | 26449 + 42 = 26491 | 35039 − 20160 = **14879** |

B は `可哀想 → な → 思い → を → さ → セタ`。`可哀想→な` −8253、`思い→を` −4993、`を→さ` −5635 が大きい。機能語接続は直るが末尾のカタカナ表記は残った。

## 悪化した代表例

### 1. `ajimee-jwtd-v2-1702` — CER 0.4000 → 1.6000（+1.2000）

- 正解: `に混声合唱`
- A: `に懇請合唱`
- B: `二懇請がっしょう`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 5.317 + 0.110 = **5.427** | 12.261 + 0.370 = 12.631 |
| IPADIC | 13237 − 3450 = 9787 | 25600 − 17005 = **8595** |

B は `二 → 懇請 → が → っしょ → う` を選んだ。`っしょ→う` の −9967 など局所的に極端な接続報酬が、IME として不自然な表記・分割を総コストで勝たせた。CER は仮説が正解より長いため 1 を超える。

### 2. `ajimee-jwtd-v2-1570` — CER 0.0000 → 1.0000（+1.0000）

- 正解/A: `して迎え`
- B: `仕手無代え`

| 目的関数 | A-path | B-path |
|---|---:|---:|
| current | 3.582 + 0.080 = **3.662** | 8.525 + 0.240 = 8.765 |
| IPADIC | 18851 − 3972 = 14879 | 15549 − 2677 = **12872** |

現行 overlay の `して` は IPADIC に同一の単一形態素がなく、B では `し + て` の IPADIC マクロとして正確に再採点した。その結果、形態素解析辞書の生起コストでは `仕手 → 無 → 代え` が安くなり、現行の完全一致を失った。これは matrix だけでなく、overlay を IPADIC 生コスト基準へ切り替える際の実害を示す。

## overlay 代理値の感度分析

IPADIC に同一 reading/surface 経路がない 5 overlay 辺の word cost を変えた。

| 代理 word cost | mean CER | 完全一致 | 主実験から出力が変わった件数 |
|---:|---:|---:|---:|
| 3000（楽観的に安い） | 0.343570 | 6.5% | 3 |
| 13069（主実験、HIRAGANA unknown） | 0.344480 | 6.5% | 0 |
| 100000（実質無効） | 0.344480 | 6.5% | 0 |

主実験で代理辺は 1-best に一度も採用されず、無効化しても結果は完全同一だった。かなり有利な 3000 にしても CER 0.343570 で A の 0.341433 を下回らない。したがって、**5 辺の代理値は「B が aggregate CER を改善しなかった」という結論を左右していない**。

## 判断と未検証事項

### 実測で確認できたこと

1. `matrix.def` は期待どおり効くケースがある。`ajimee-jwtd-v2-305`、`965` では、現行 16-POS 表が表現できない強い機能語接続が正しい分割を選んだ。
2. 効果は一方向ではない。183/200 件の出力を変え、69 件を悪化させた。IPADIC の局所接続が形態素解析には妥当でも、読みから表記を生成する IME の目的には妥当でないケースが多い。
3. `matrix.def` 取り込みだけで CER 0.15〜0.22 に届くという見積もりは否定された。今回の同目的関数比較では 0.344480 で、baseline より僅かに悪い。
4. overlay は単純に IPADIC 生コストへ戻せない。`して迎え` のような現行の正解を失うため、P1 を行うなら overlay 用の別スケール・ID 設計が必要になる。

### 未検証

- **現行 BeME 生起コストを残し、`matrix.def` だけを BeME スケールへ変換して加える hybrid 目的関数**は未検証。これは今回指定された「IPADIC と同じ目的関数」ではなく、倍率・offset・overlay との相互作用を持つ別モデルである。
- matrix の倍率、カタカナペナルティ、overlay 生起コストを AJIMEE 上で同時調整すれば改善する可能性はある。ただし同じ 200 件で調整・評価すると過適合になるため、開発/評価分割または別コーパスが必要。
- 本実験は AJIMEE 200 件上の判断であり、Mozc 498 件や実ユーザー入力への一般化は未検証。
- beam 64 という指定条件での比較である。IPADIC 目的関数で beam を増やした場合は未検証。
