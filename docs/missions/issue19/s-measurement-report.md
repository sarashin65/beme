## 1. 測定の定義

PLAN §3.1 に従い、**4 粒度 × 2 候補集合 × 3 率**を測った。

**4 粒度**

| 粒度 | 定義 | キーの取り方 |
|---|---|---|
| (a) `lex14` | `decomposed_v1` の lexical 14 次元のみ完全一致 | bit-exact（`repr()` ベース） |
| (b) `lex9` | A8（`decomposed_v1-no_script-surface_len`）の lexical 9 次元のみ完全一致 | bit-exact |
| (c) `full25` | A8 の全 25 次元（lexical + transition）完全一致 | bit-exact |
| (d) `cost` | A8 初期重みでのパスコスト同点 | `math.isclose(rel_tol=0, abs_tol=1e-12)` |

粒度 (a)〜(c) が bit-exact なのは、「特徴ベクトルが同一 ⇒ **どんな重みでも**順位付け不能」という主張が丸めを許さないため。粒度 (d) だけ絶対許容誤差を使うのは、パスコストが約 25 個の重み付き特徴の総和であり、異なるベクトルが浮動小数点の丸めで同じ値に落ちうるから — 線形モデルがタイブレークに落ちるかどうかという実運用の問いに対しては、絶対許容誤差のほうが正しい定義である。

**2 候補集合**

- **主測定 = v2 lattice の k-best**（k = 64・beam 64）。学習は JSONL の `candidates` 列を使わず、読みから lattice を張り直して `constrained_best_path` と比べる（`src/beme/training.py:178-183`）。したがって局所モデルが実際に順位付けしている集合はこちらである。
- **副測定 = JSONL の `candidates` 列**（v1 辞書由来・平均 49.4 候補/ケース）。Opus の見積りと d1 生成時の設定に橋を架けるために残す。各候補表記は `constrained_best_path` で lattice 上のパスに写して評価した（写せなかった候補は `candidate_unreachable` として計上 — 実測 0 件）。

**3 率**（いずれも分母は **gold 到達可能ケース数**。到達不能ケースは分子・分母の双方から除外する）

1. `any_tied_pair_rate` — 候補集合中に同点対を 1 組でも含むケースの割合
2. `top2_tied_rate` — 最安 2 候補が同点であるケースの割合
3. `gold_vs_nongold_tied_rate` — **gold と非 gold が同点であるケースの割合**（意思決定に効く唯一の指標）

gold パスは `oracle.constrained_best_path(lattice, target_surface, cost_scorer)` で取る。これは学習側が正解経路を取るのと同じ関数であり、gold が k-best に入っていないケースでも gold 側のキーは得られる（率 3 は k-best 内の全候補と比較する）。

### 2.3 読み方

- **`any_tied_pair_rate` が 9 割前後なのは驚くに値しない。** 64 件の候補集合の中に「どこかに同点対が 1 組でもある」確率であり、大半は下位の無意味な候補どうしの同点である。意思決定には使えない指標であり、PLAN が 3 つ目の率を「唯一の指標」と書いたのはこのためである。
- **粒度 (c) と (d) の差は小さい**（test で 8.65% vs 8.70%、train で 9.60% vs 9.72%）。全 25 次元が一致すればコストも必ず一致するので (c) ≤ (d) であり、その差 0.05〜0.12 pt が「特徴は違うのに A8 初期重みではコストが一致してしまう」ケースにあたる。**現行重みのタイブレーク落ちのほぼ全量が、重みでは救えない真の同点である。**
- **粒度 (a) < (b) ≈ (c)** という順序は逆に見えるが正しい。lex14 は `script.*` と `surface_len` を含む**より情報量の多い**特徴集合なので、一致しにくい（同点率が低い）。A8 がこれらを落としたぶん lex9 の同点率が 0.95〜1.15 pt 上がっている — issue #17 の A8 採用が同点をわずかに増やした代償が、ここで初めて定量化された。
- **lattice と JSONL の差は `any_tied_pair_rate` に集中し、`gold_vs_nongold_tied_rate` はほぼ一致する**（差 0.05〜0.16 pt）。JSONL 候補列は v1 辞書由来で lattice k-best より狭いため「どこかに同点」は起きにくいが、gold の周辺の同点構造は両者で同じである。**主測定と副測定は同じ結論を出しており、Opus の見積りとの橋渡しに副測定を使うことは妥当**と確認できた。

### 2.4 副産物 — gold の順位分布と「同点でないのに順序が誤っている」ケース

v2 lattice k-best（k=64）上での gold の順位:

| gold の順位 | test（2,000） | train（10,000） |
|---|---|---|
| 1 位 | 1,380（69.0%） | 6,824（68.2%） |
| 2 位 | 260（13.0%） | 1,231（12.3%） |
| 3 位 | 120（6.0%） | 614（6.1%） |
| 4〜10 位 | 186（9.3%） | 966（9.7%） |
| 11〜64 位 | 54（2.7%） | 365（3.7%） |
| k-best 圏外 | 0（0.0%） | 0（0.0%） |

**gold が k-best 圏外に落ちたケースは 0 件**（k = 64・beam 64）。したがって以下の議論で「探索が gold を落としている」可能性は排除できる。

`misranked_not_tied`（gold が 1 位でなく、かつ gold と 1 位候補の全 25 次元が**異なる**ケース）:

| split | gold が 1 位でない | うち非同点（misranked_not_tied） | うち 1 位と full25 同点 |
|---|---|---|---|
| test | 620（31.0%） | **574（28.7%）** | 46（2.3%） |
| train | 3,176（31.8%） | **2,947（29.5%）** | 229（2.3%） |

読み方: 現行 A8 重みで gold を 1 位に持ってこられていない 31.0%（test）のうち、**同点で落ちているのは 2.3 pt だけで、残り 28.7 pt は「特徴上は区別できるのに重みが誤って並べている」**。F2 が同点解消として効く上限は前者側にあるが、新しい特徴次元が加わることで後者の順序が改善する可能性は否定されない（それは F2 の効果測定 = task5 が答える問いである）。この 28.7% は「同点でないから局所モデルの上限ではない」領域であり、**局所モデルの真の天井は 8.65% の同点よりずっと低い位置にはない**ことを示している。

### 3.1 なぜ「読みが辞書にある率 86.75%」なのに「gold 到達率 100%」なのか

矛盾ではない。`build_lattice(..., allow_literals=True)` は辞書に無い読みに対してもリテラル（かな表記そのまま）ノードと未知語ノードを張るため、**どんな読みでも lattice は連結し、gold 表記は分割・未知語経路を通じて必ず構築できる**。13.25%（test）は「読み全体が単一の辞書エントリとして引けない」ケースであり、その多くは複合語で、部分語の連結として lattice 上に存在する。§3 のトークン数分布（test の 13.6% が 2 トークン以上）がこの 13.25% とほぼ一致するのは同じ現象を別の角度から見ているからである。

**分岐 B への含意**: 「どんな特徴を足しても解けない」ケースは 0 件である。F2 より辞書側（B 項目の固有名詞層）を先に出す根拠は d1 上には存在しない。ただしこれは「d1 の gold が必ず lattice 上にある」という到達可能性の話であって、「正しく 1 位に来る」という話ではない（後者は §2.4 の 31.0%）。

## 4. Opus アドバイザリーの辞書レベル 24.9% と、d1 候補集合上の lex14 率の比較

**結論を先に**: 24.9%（辞書レベル）と 7.80%（d1 test・lex14・lattice・gold vs 非 gold）は**直接比較してはいけない**。分母も母集団も異なる。ケース単位に揃えた最も近い量は `any_tied_pair_rate` = **89.65%** であり、こちらは逆に 24.9% を大きく上回る。両方向にずれるのは、二つの数字が別の質問に答えているからである。

### 4.1 何がどう違うのか

| | Opus の辞書レベル 24.9% | task1 の d1 lex14 率 |
|---|---|---|
| 母集団 | v2 辞書の**多候補読み**（本測定での再カウント: 表記が 2 種以上の読み **70,905** 件 / 全 201,904 読み。アドバイザリーの 72,013 は品詞違いを別エントリとして数えた値と解釈される） | d1 train+test の**ケース**（12,000 件・ユニーク読み **9,778** 種） |
| 数える単位 | 読みの中の**候補対** | **ケース**（同点対を 1 組でも含むか / gold が同点か） |
| 候補の作り方 | 辞書エントリの直積（単一エントリのみ） | v2 lattice の k-best（**複数トークンの連結を含む**・test の 13.6% が 2 トークン以上） |
| 読みの引かれ方 | 辞書の見出し語を一様に | **実文書中の出現頻度**に従って（d1 は Wikipedia 由来） |

### 4.2 分布の違いを実測した

- d1 のユニーク読み 9,778 種のうち、v2 辞書に見出しとして存在するのは **7,698 種**、そのうち多候補（表記 2 種以上）なのは **4,327 種**。
- d1 に現れる（辞書にある）読み 1 件あたりの辞書表記数の平均は **3.26**。辞書全体の平均は **1.69**。

つまり **d1 は辞書よりも「曖昧な読み」に偏って引いている**（頻出語ほど表記の異なり数が多いため）。母集団が違うだけでなく、**難しい方向に**違う。24.9% をそのまま d1 の同点率の予測値として使うと、辞書側の一様サンプリングが d1 の頻度重み付きサンプリングを過小評価する方向にずれる。

### 4.3 24.9% を再現しようとしないほうがよい理由

辞書レベルの候補対率を d1 のケース率に写す変換は、(i) 読みの頻度重み、(ii) 多トークン連結の寄与、(iii) k-best の打ち切り（k=64）、(iv) 「対」から「ケース」への集約、の 4 つを同時にモデル化しないと成立しない。task1 は変換を推定するのではなく、**F2 の意思決定に必要な量（gold と非 gold の同点率）を d1 上で直接測った**。24.9% は「辞書の中にどれだけ潜在的な曖昧性があるか」という設計上の傍証としては有効だが、**F2 の期待効果の見積りには使えない**。使うべき数字は 8.65%（粒度 c・test）である。

## 5. 分岐判定と F2 の期待値への含意

### 5.1 分岐 A → 中段（3〜10%）: 理論上限を事前登録する

粒度 c（A8 全 25 次元）・v2 lattice・test で **8.65%**。10% の閾値をわずかに下回り、3% を大きく上回る。PLAN の規定どおり **F2 は本命として進める** が、**学習前に理論上限を事前登録する**。

> **事前登録（task4/task5 の学習・評価より前に確定）**
>
> **F2（コーパス頻度 3 特徴）が「同点解消」として d1 test の top-1 精度に寄与しうる理論上限は 8.65 pt である。** 内訳: gold が非 gold と全 25 次元で同点になるケースが 2,000 件中 173 件。この 173 件を F2 が**すべて正しい向きに**解消して初めて 8.65 pt が実現する。現実には (i) コーパス頻度が gold 側を支持しないケース、(ii) 同点解消が別のケースを壊す副作用、(iii) task3 の (読み,表記) 被覆率が 100% 未満であること、の 3 つが上限を削る。**したがって 8.65 pt は達成目標ではなく、これを超える改善が観測されたら同点解消以外の経路（§2.4 の 28.7% の順序誤り側）が効いたと解釈すべき上界である。**
>
> 参考上限として、粒度 d（A8 初期重みでのコスト同点）では 8.70 pt、train では粒度 c で 9.60 pt。

さらに、**F2 が触れる 3 特徴のうち 2 つは同点ケースの全件には効かない**点を記録しておく。粒度 c の同点は「gold と非 gold の (読み,表記) が両方とも同じ特徴値を持つ」ことを意味するが、F2 の `lex.corpus_reading_cond_logprob` は読みを共有する候補どうしを**必ず**区別する（`c(r,s)` が異なれば値が異なる）ため、**同点を解消する能力そのものは構造的に保証されている**。解消されない残余は「両候補とも `c(r,s) == 0`」のケースに限られ、その規模は task3 の分岐 C 被覆率が決める。

### 5.2 分岐 B → 該当せず

gold 到達不能率は train・test ともに **0.00%**（0 / 12,000）。5% の閾値に遠く及ばない。**「F2 より辞書側（B 項目の固有名詞層）が先である」と task7 に書く条件は満たされない。** d1 上では、どんな gold 表記も lattice で構築可能であり、問題は到達可能性ではなく順位付けである。

これは B 項目が不要という意味ではない。d1 は Wikipedia 由来で、固有名詞層の弱さが最も出るのは d1 の外（AJIMEE・handmade スイート）である。**task1 が言えるのは「d1 に関する限り到達可能性は制約になっていない」までである。**

### 5.3 分岐 C → task3 へ引き渡し

task1 は分岐 C の入力を生成した:

- `artifacts/issue19/s-measurement/coverage_pairs.jsonl` — d1 train+test の gold (読み,表記) ペアの多重集合。**10,342 ユニークペア・出現数合計 12,000**（= ケース数と一致）。task3 はこのファイルの各ペアについて `c(r,s) > 0` を判定し、test 側の割合を分岐 C の判定値とする。
- 参考値として、gold ペアが **v2 辞書**に単一エントリとして存在する率は test 86.50% / train 81.59%。コーパス被覆率はこれとは独立で、**辞書に無いペアがコーパスにある**ことも**その逆**もありうる。

## 6. 実装レビューの所見と修正

PLAN §3.1 の定義との突き合わせで **2 件の欠陥を検出し、修正した**（`src/beme/` は一切変更していない — 修正は `scripts/` と `tests/` のみ）。

### 6.1 修正 1（実害あり）— gold ペアの二重計上

`_analyze_candidate_set()` が `gold_pair_multiset` を加算していたが、この関数は 1 ケースにつき lattice 側と JSONL 側の**2 回**呼ばれるため、`coverage_pairs.jsonl` の全カウントが**正確に 2 倍**になっていた（合計 24,000 = 12,000 ケース × 2）。

**このファイルは分岐 C を判定する task3 の入力であり、放置すれば被覆率の重み付けが歪む。** 加算を `_process_split()` 側の「gold が到達可能と判定された箇所」に 1 回だけ移し、回帰テスト `test_gold_pair_counts_are_not_double_counted` を追加した（3 ケース・2 表記の最小構成で、期待カウントを完全一致で検証する）。修正後の合計は **12,000**（= ケース数）に一致する。

### 6.2 修正 2（潜在）— 率の分子と分母の母集団のずれ

`gold_vs_nongold_tied_rate` の分子は gold 到達不能時に必ず False になるので正しかったが、`any_tied_pair_rate` と `top2_tied_rate` の分子は**到達不能ケースも数えていた**。分母は 3 率とも `gold_reachable` なので、到達不能ケースが存在すれば前 2 率が 1.0 を超えうる。

d1 では `gold_unreachable = 0` のため**この欠陥は本レポートの数値に一切影響していない**（修正前後で `ties.json` の SHA-256 が `f5972c81…` のまま不変であることで確認済み — 意図せぬ副作用が無かったことの実測的な証明でもある）。将来 d1 以外のデータで走らせたときのために、3 率すべてを gold 到達可能ケースのみで数えるよう揃えた。

### 6.3 修正 3（記録の正確性）— 使われない `--k`

`--k` は `ties.json` の manifest に記録されるが、`Lattice.k_best(beam_width, scorer)` には k の独立した引数が無く（beam がそのまま k）、`--beam-width` しか探索に届いていなかった。両者が既定値 64 で一致していたため実測値には影響しないが、**走らせていない設定が manifest に残る**のは再現性の記録として誤りである。`--k != --beam-width` を明示的に拒否するようにし、テスト `test_k_must_equal_beam_width` を追加した。

### 6.4 問題なしと確認した点

- **bit-exact キー**（`tuple(sorted((name, repr(value)) ...))`）: `repr()` は float のビットパターンを完全に保存し、名前でソートすることで挿入順に依存しない。「どんな重みでも順位付け不能」という粒度 (c) の主張には丸めを一切許さないこの定義が正しい。
- **コスト同点の `math.isclose(rel_tol=0, abs_tol=1e-12)`**: 粒度 (d) だけが「約 25 個の重み付き特徴の総和」という浮動小数点の累積誤差を含むため、絶対許容誤差を使うのは妥当。`rel_tol=0` により、値の大小に依存しない純粋な絶対バンドになっている。
- **gold パスの取得**: `oracle.constrained_best_path(lattice, target_surface, cost_scorer)` は `src/beme/training.py:178-183` が正解経路を取るのと同一の関数・同一のスコアラーであり、学習が見ている gold と一致する。
- **gold が k-best 圏外のケースの扱い**: gold 側のキーは k-best とは独立に `gold_path` から作られるため、圏外でも率 3 は全候補と比較できる（実測では圏外 0 件）。
- **JSONL 候補の lattice への写像**: 各候補表記を `constrained_best_path` でパス化することで、2 候補集合が**同一の特徴抽出器・同一のスコアラー**で評価される。写像不能は 0 件。
- **非ひらがな読み**: `build_lattice` の `ValueError` を捕捉して到達不能として計上し、スコアラーの挙動と整合させている。
- **テストの実質性**: 5 件（修正で 7 件）はいずれも `tmp_path` に手書き辞書と JSONL を作って**サブプロセスでスクリプトを実行する**エンドツーエンドテストであり、キーの存在だけでなく「同点構成で全率 1.0」「非同点構成で全率 0.0」「到達不能で分母から除外」という**値**を検証している。形だけのテストではない。gitignore された `data/d1/*.jsonl` に触れないので、クリーンな CI チェックアウトでも通る（`test_does_not_depend_on_d1` が明示的に検証）。

## 8. 既知の限界

1. **単一測定・単一 split**。seed による分散は測っていない（この測定は決定論的で、乱数を使う箇所が無いため seed 反復に意味が無い）。train と test の差に統計的な意味を読み込まないこと。
2. **k = 64 の打ち切り**。gold の k-best 圏外は 0 件なので gold については影響が無いが、`any_tied_pair_rate` は k に単調増加する量であり、k を変えれば動く。粒度 c の `gold_vs_nongold_tied_rate` は「k-best 内の非 gold との同点」なので、k を広げれば増えうる（上限 8.65 pt はこの k での値である）。
3. **同点の「向き」は測っていない**。173 件（test・粒度 c）の同点のうち、コーパス頻度が gold を支持する割合は task3/task4 が測る。8.65 pt はその全件が正しく解消される仮想の上限である。
4. **JSONL 副測定は v1 辞書由来の候補列を v2 lattice 上で再評価している**。d1 生成時の v1 辞書上のコスト（`viterbi_costs` 列）とは別物であり、両者を混同しないこと。
5. **`smoke.json` は修正前のコードで生成された**（test 先頭 500 件・`--limit 500`）。§6.1 の二重計上は `coverage_pairs.jsonl` にのみ現れる欠陥で `ties.json` 系の値には影響しないため、事前スモークとしての参照価値は保たれている。本測定の値はすべて修正後の `ties.json` から引いた。
