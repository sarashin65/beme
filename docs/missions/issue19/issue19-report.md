# issue #19 レポート — 「局所モデルは過少適合している」の検証と F2（コーパス頻度特徴）の導入

- 対象: [issue #19](https://github.com/sarashin65/beme/issues/19)
- 日付: 2026-08-30（task1〜task6 の実測に基づく）
- 実行機: ローカル（miniPC）+ GPU（ws）

## 0. 結論

**F2（コーパス頻度 3 特徴）は採用された。** C0（A8 + corpus 3 特徴）は A8 に対して test 誤り **520 → 309（-40.6%）**、ペア McNemar は 3 seed すべて p ≤ 6.4e-32（事前登録の採用基準を充足）。issue #19 の前提のうち、**「局所モデルは過少適合している」は支持**（task2 の lr スイープで最適化要因を排除し、train 誤差 27.2〜28.0% の帯に収まることを確認）、**「局所側に取り残しがある」も支持**（F2 が同点解消の理論上限 8.65pt を超えて効き、順序誤り側にも語彙知識の取り残しがあった）。さらに task6 により、Phase 4 の CE リランカ（LR）が買った overall +10pt は**ほぼ全て語彙成分で説明できる**ことが分かった。語彙化した局所モデルは文脈モデルより桁違いに安く、実用 IME の構成として有力である。

## 1. 前提の確認（task1: S 実測）

`scripts/measure_local_ceiling.py`（Ornith 実装・Opus レビュー）で d1 test 2,000 ケースの候補集合を実測した。

| 項目 | 実測値 | 判定 |
|---|---:|---|
| 分岐 A: gold vs 非 gold 同点率（粒度 c・v2 lattice・test） | **8.65%**（173/2,000） | 中段（3-10%）→ F2 は進める・**理論上限 8.65pt を事前登録** |
| 分岐 B: gold 到達不能率 | **0.00%**（0/12,000） | 該当せず（辞書側を優先する根拠なし） |
| 読み辞書被覆率（test） | 86.75% | — |
| (読み,表記) 被覆率（test） | 86.50% | — |
| gold 到達可能 | 100% | — |

**同点より 3.3 倍大きい未回収プール**: gold が 1 位でない 620 件（31.0%）のうち、同点で落ちているのは 46 件（2.3%）だけ。残り **574 件（28.7%）は misranked_not_tied** = 特徴上は区別できるのに現行重みが誤って並べている。F2 が同点解消として効く上限は 8.65pt であり、**これを超える改善が観測されたら「順序誤り側（28.7%）が効いた」と解釈する**ことを事前登録した。

**Opus の辞書レベル 24.9% との関係**: 直接比較不可（母集団・単位・頻度重みが全て異なる）。d1 は辞書より「曖昧な読み」に偏って引かれている（読み 1 件あたり辞書表記数 3.26 vs 辞書全体 1.69）。F2 の期待効果見積りに使う数字は **8.65%**。

## 2. 最適化要因の排除（task2: lr / epoch スイープ）

「28% は容量由来」を確定するため、A8 base・`train_scorer.py` をそのまま（コード変更ゼロ）lr 0.01〜1.0 × epoch 5/20 でスイープした（12 run 設計・10 run 実行・GPU ws）。

| lr | ep=5 | ep=20 |
|---|---:|---:|
| 0.01 | .2795 | .2751 |
| 0.03 | .2729 | .2729 |
| 0.1（現行） | .2728 | .2733 |
| 0.3 | .2727 | .2727 |
| 1.0 | .2725 | .2730 |

**判定: 最適化要因は排除。「28% は容量由来」が確定した。** どの lr・epoch でも train 誤差は **27.2〜28.0% の帯**に収まる（ばらつき <0.7pt）。24% を下回る設定は存在しない。学習自体は効いている（baseline 31.76% → 平均化重み 27.3% = 4.4pt 改善）が、そこから先に進まない。30 パラメータの線形モデルでは訓練データから学びきれない。

F2 への申し送り: lr は現行 0.1 のままで問題なし。

## 3. F2 の実装（task3: コーパス頻度表・task4: 3 特徴の実装）

### 3.1 特徴の定義（事前登録・平滑化なし）

トークン (読み r, 表記 s) について、表から c(r,s) / c(s) / c(r) / N を引く:

| 特徴 | 値 | 意味 |
|---|---|---|
| `lex.corpus_reading_cond_logprob` | `-log(c(r,s)/c(r)) / T`（c(r,s)>0 のみ・他 0.0） | 読み条件付きの表記選択コスト |
| `lex.corpus_unigram_logprob` | `-log(c(s)/N) / T`（c(s)>0 のみ・他 0.0） | 表記ユニグラムコスト |
| `lex.corpus_unseen` | `c(r,s)==0 → 1.0`・他 0.0 | 未観測ペアフラグ |

- **符号**: 負の対数確率（コスト最小化に整合・他の lexical 特徴と向きを統一）
- **平滑化なし**: 未観測時の定数オフセットは `lex.corpus_unseen` の学習重みが担う（α を人手で選ばず学習可能量にする）
- **スケール** `T = CORPUS_LOGPROB_TEMPERATURE = 10.0`: d1 test gold 2,000 件での実測 std（最大 0.4132）が `lex.ipadic_cost_mapped`（2.2423）の 3 倍以内に収まることを確認して**学習前に固定**（値の上限は構造的に `log(11,646,065)/10 ≈ 1.63`）
- **分岐 C**: `d1_test_gold_pair_coverage = 0.856 ≥ 0.70` → 4 特徴目 `corpus_surface_unseen` は追加しない

### 3.2 リーク対策 3 重（task3）

1. `article_split` を `build_d1_data` から **import**（写経ゼロ・grep で確認）
2. `overlaps_evaluation` 適用（d1 と同じく 3 記事除外）
3. 監査双方向: counted ∩ d1 dev/test = **0**・d1 dev/test の train 誤分類 = **0**（194 記事・独立再計算で一致）

## 4. F2 の結果（task5: 学習実行とアブレーション判定）

GPU ws で 12 run（A0/A8/C0/C1 × seed 9/17/33・epochs 5・lr 0.1）。A8/A0 も同日・同機で再実行（機差の交絡を回避）。

### 4.1 test 誤り件数（小さいほど良い）

| 条件 | seed9 | seed17 | seed33 | 中央値 | vs base |
|---|---:|---:|---:|---:|---|
| A0 | 529 | 533 | 539 | 533 | — |
| A8（現行 base） | 521 | 520 | 520 | 520 | — |
| **C0**（A8+corpus3） | **309** | **308** | **315** | **309** | **-40.6% vs A8** |
| **C1**（A0+corpus3） | **281** | **279** | **276** | **279** | -47.7% vs A0 |

### 4.2 McNemar（C0 vs A8・診断データの per-case を id で突き合わせ）

| seed | b（A8正解&C0誤り） | c（C0正解&A8誤り） | p 値 |
|---|---:|---:|---:|
| 9 | 47 | 259 | 1.7e-33 |
| 17 | 48 | 260 | 2.7e-33 |
| 33 | 48 | 253 | 6.4e-32 |

**3 seed すべて p << 0.05 かつ誤り中央値 309 < 520 → 採用**（事前登録 §2.4 どおり）。C1 vs A0 も p ≈ 1e-39〜1e-44 で有意。

### 4.3 解釈

- **8.65pt の理論上限を超過**（改善約 10.5pt = 40.6%）→ 事前登録どおり**順序誤り側（misranked_not_tied 28.7%）にも有効**と解釈。同点解消だけでなく、誤って並べた候補を正しい順序に直す力がある
- **base 依存の観察**: C1（A0+corpus）が C0（A8+corpus）より 3 seed 全部で良い（279 vs 309）。A0 vs A8 の差（13 件）より C1 vs C0 の差（30 件）が大きく、A8 で削った script/surface_len 特徴が corpus 頻度と相乗する可能性（深掘り候補）

### 4.4 学習後の corpus 重み（C0・3 seed 安定）

| 特徴 | 重み | 期待符号 |
|---|---:|---|
| `lex.corpus_unigram_logprob` | +0.52〜+0.57 | 正（頻出表記を優遇）✓ |
| `lex.corpus_unseen` | +1.84〜+2.28 | 正（未観測ペナルティ）✓ |
| `lex.corpus_reading_cond_logprob` | -0.10〜-0.14 | **負（期待と逆）** |

`reading_cond_logprob` の逆符号は、d1 gold 上で `corpus_unseen` と `corpus_unigram_logprob` が完全共線（coverage 0.856 一致 = ペア未観測 ⟺ 表記未観測）であることと整合する多重共線の残差調整と解釈する。**個々の重みの単独解釈はしない**（モデル全体の効果 -40.6% で判断）。

### 4.5 直し / 壊し（C0 vs A8・seed9）

- FIXED 259 件: ふくせい→**複製**（A8 は復姓）・きょうぎ→**競技**（協議）・せいねん→**生年**（青年）— 「頻度の高い正しい表記」を拾う典型
- BROKEN 47 件: うしろ→後（gold 後ろ）・のぞむ→望む（臨む）— 頻度の高い別表記に引っ張られた副作用（文脈で解決すべき残差）

### 4.6 実行上の障害と対処（記録）

1. A0/seed9 のゲートが過去実績（538）と不一致で停止 → baseline 620 が完全一致したことから機差と判断し、**ゲートの expected を今回の実測（529/1471/0.286716/84）に更新**（判定基準は不変・理由コメント付き）
2. C0/C1 の初期重み（`*corpus_v1.json`）の ws 転送漏れで 6 run 失敗 → scp 後に再実行し完走

## 5. 語彙成分と文脈成分の分離（task6: Phase 4 contrast 再測）

`rerank_eval.py`（mock reranker・コード変更ゼロ）で A8 / C0 × seed 9/17/33 を測定。文脈を見ない C0 の `both_correct` は 0 のまま overall がどれだけ上がるか = 語彙成分の見積り。

### 5.1 4 指標（中央値）

| 条件 | overall Top-1 | 誤り | non_contrast | contrast | both_correct |
|---|---:|---:|---:|---:|---:|
| A8 | .7400 | 520 | .7692 | .3125 | **0/64** |
| **C0** | **.8455** | 309 | **.8755** | .4063 | **0/64** |

- 予測①: **C0 の both_correct = 0/64（全 seed）** — 文脈盲の確認（0 でないケースなし・測定/実装は健全）
- 予測②: **non_contrast_top1 が .7692 → .8755（+10.6pt）**

### 5.2 分離の見積り

```
LR の overall gain (Phase 4)          : +10.05 pt  （.7310 → .8315・参照値・機と日付が異なる）
C0 の overall gain (対 A8・同日同機)   : +10.55 pt  （.7400 → .8455）← 語彙成分の下限見積り
残差 (X − Y)                          : -0.50 pt   ← 文脈成分 + 交絡の上限見積り
C0 の both_correct                    : 0/64       ← 予測どおり 0
```

**注記**: この引き算は**上限/下限の粗い見積りであって厳密な分解ではない**。L（Phase 4）と C0（task5）は base（A0 vs A8）も学習日も異なる。単一 split の差に p 値は付けない。

### 5.3 解釈

- **Phase 4 の LR が買った +10pt はほぼ全て語彙成分で説明できる** — 「30 パラメータのモデルが持てない語彙知識を CE が肩代わりしているだけの部分があるなら、その部分は語彙化した局所モデルで CE よりずっと安く取れる」という issue #19 の仮説が overall の観点でほぼ全域成立
- **文脈の優位は contrast ペアに限定**: C0 の contrast .4063 vs LR の .5313（差 .125 ≈ 文脈の純粋寄与の目安）。真に曖昧な 128 件では CE がまだ勝つが、overall への寄与は小さい

## 6. issue #19 の「提案するアクション」3 項目への回答

### 1. 平均化重みで train split を評価（安い前提確認）→ **実測済み・過少適合が確定**

平均化重みでの train 誤差は **28.2%**（task2 で lr/epoch を振っても 27.2〜28.0% の帯に収まる）。train 誤差 > dev 誤差（約 9pt 差）のまま平坦であり、過少適合が確定した。

### 2. 語彙化した局所モデルの検討 → **F2 で実証・採用**

F2 は「疎な語彙重み（単語ごとの学習可能な重み）」ではなく「**外部頻度表を 3 個のスカラー特徴で読む**」形である点に注意。この違いは重要で、F2 は学習パラメータを増やさずに 34 万ペアの語彙知識を注入した。F2 の成功は、着手順序表の B 項目（疎な語彙重み pair + backoff）の**期待値を強く示唆する** — 語彙知識そのものに大きな価値があることが実証された。ただし実装形態（疎重み vs 表参照）の優劣は B 項目の実験でしか決まらない。

### 3. 分離実験 → **task6 で実施**

語彙成分の下限 +10.55pt・文脈+交絡の上限 -0.50pt・both_correct 0/64（§5）。

## 8. 限界と残存リスク

- **コーパス側の重複**: article_id ベースのフィルタは、別記事に同一文が重複している場合（Wikipedia のコピペ節）を防げない。d1 生成時の正規化グループ重複除去はケース側の対処であり、コーパス側の重複は追っていない
- **F2 の被覆率が上限を決める**: 表に無いペアには `lex.corpus_unseen` しか効かない。被覆率（task3 実測 0.856）が F2 の効く範囲の上限である。被覆を上げるには表の再ビルド（より大きなコーパス）か辞書拡張が必要
- **corpus 重みの多重共線**: `unseen` と `unigram_logprob` は d1 gold 上で完全共線。個々の重みの単独解釈は不可
- **contrast の 64 組は小さい**: 単一 split・単一 seed の差に p 値ラベルを付けていない（Phase 3/4 のレポート規約）
- **機差**: A0/seed9 のゲート値が過去実績からずれた（baseline 620 は完全一致 → 環境再現は確認済み）。再現実験の数値はこの環境の値として解釈すべき
- **C1 と C0 の base 依存**: なぜ A0 上で corpus がより効くのかは未解明（script/surface_len との相乗仮説）
