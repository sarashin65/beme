# BeME 変換精度 深掘り分析（AJIMEE CER 0.341）

**日付**: 2026-08-21
**対象コミット**: `24a422b`（IPADIC 取り込み後）
**測定環境**: `.venv`（Python 3.13.5）、`data/dictionary.tsv` 349,043 エントリ、beam_width=64、top_k=5、reranker=mock

---

## 0. 要約（先に結論）

再現した基準値: **mean CER 0.3414 / 完全一致 6.0% / mean edit distance 6.56**（AJIMEE 200 件）。

200 件をオラクル分解した結果、失敗の内訳は次のとおり。

| 分類 | 件数 | 比率 | CER 寄与 |
|---|---:|---:|---:|
| **モデル誤り（分割）** | 101 | 50.5% | 57.4% |
| **モデル誤り（同音・表記選択）** | 60 | 30.0% | 27.1% |
| **辞書欠落（未知語）** | 25 | 12.5% | 13.5% |
| 正解 | 12 | 6.0% | 0.0% |
| 探索誤り（ビーム脱落） | 2 | 1.0% | 2.0% |

**事前仮説との差分**: 「未知語・辞書欠落が主因」という見立ては**実測では支持されない**。
正解文字列は 200 件中 175 件（87.5%）で **ラティス上に到達可能な経路として存在している**。
にもかかわらず 1-best に出てこないのは、**コスト関数がその経路をより高コストと判定しているから**である。
つまり現在の律速は辞書ではなく **コストモデル（特に接続コストの欠落）**。

根本原因を一文で言えば:

> BeME は MeCab IPADIC の**単語生起コスト**だけを取り込み、**接続コスト（matrix.def, 1316×1316）を捨てて 16×16 の手書き POS 表に置き換えた**。IPADIC の接続コストは中央値で −2,000〜−4,600（BeME スケールで −1.0〜−2.3）という**大きな負の報酬**であるのに対し、BeME の遷移コストは +0.03〜+0.20 の**小さな正の罰**しかない。判別信号の符号と桁が失われている。

さらに重要な追加事実として、**16 個の粗い POS ラベルへ潰した時点で matrix.def の分散の 79% が失われる（R² = 0.21）**。
「POS 遷移表をうまくチューニングすれば追いつける」という道は原理的に閉じている（§4・§5 で実測により裏づけ）。

## 1. 測定方法

### 1.1 基準値の再現

```sh
.venv/bin/python scripts/evaluate.py --suite ajimee --json
# mean_cer=0.3414330939157979, exact_match_accuracy=0.06, mean_edit_distance=6.56
```

README 記載値と一致。以降の全数値はこの構成を基準とする。

### 1.2 オラクル分解（失敗分類の方法）

比率を推測でなく実測にするため、`src/beme/lattice.py` と `src/beme/benchmark.convert_sentence` の
コスト計算を**完全に模した DP**（読み位置 × 正解文字列位置 × 直前 POS）を実装し、各ケースについて

1. 正解文字列を出力する経路がラティス上に**存在するか**
2. 存在するなら、その経路のコスト（= オラクルコスト）が 1-best のコストより**高いか低いか**

を求めた。辞書に無い部分は「パッチ辺」（読み任意長 → 表層任意長、コスト 1000）で埋め、
パッチ本数を辞書欠落の指標とした（1000 は他の全コストを支配するので実質的に辞書式順序になる）。

これにより、失敗を排他的な 3 系統に切り分けられる。

- **辞書欠落 (coverage)**: パッチが 1 本以上必要 = ラティスに正解経路が存在しない
- **モデル誤り (model)**: 正解経路は存在するが `oracle_cost > hyp_cost` = コスト関数が誤った経路を選んだ
  - 分割境界が仮説と一致 → **同音・表記選択**
  - 一致しない → **分割**
- **探索誤り (search)**: `oracle_cost <= hyp_cost` なのに出力されなかった = ビーム/上位 k 打ち切りで脱落

分析スクリプトはリポジトリ外（`~/.cache/beme-diag/`）に置き、リポジトリは読み取り専用のまま変更していない。

**この分解の限界（明記）**: DP は `convert_sentence` のスパン構造（非かな文字でスパンを分割し、
各スパン先頭で直前 POS を None にリセットする）を再現しているが、スパン間のコスト合成が
`_deduplicate_candidates` により k=5 に打ち切られる点までは模していない。したがって
「探索誤り」は下振れしうる（実測 2 件）。ただし §2.4 のビーム幅実験がこの懸念を独立に否定している。

## 2. 失敗パターンの実測分類

### 2.1 モデル誤り・分割（101 件 / 50.5%、CER 寄与 57.4%）

最大のカテゴリ。仮説と正解の**トークン列の品詞構成**を比較すると偏りが明瞭に出る。

| 品詞 | 仮説での出現率 | 正解での出現率 | 比 |
|---|---:|---:|---:|
| suffix（接尾） | 0.05% | 2.22% | **1/44 に潰れている** |
| auxiliary（助動詞） | 0.37% | 2.49% | **1/6.7** |
| verb | 6.85% | 9.85% | 1/1.4 |
| **proper_noun（固有名詞）** | **4.74%** | **1.96%** | **2.4 倍に過剰生成** |
| adjective | 2.64% | 1.64% | 1.6 倍 |
| prefix | 1.63% | 0.85% | 1.9 倍 |

読み方: **接尾辞・助動詞という短い機能形態素を独立トークンとして立てられず、
より長い名詞／固有名詞・形容詞に呑み込ませている**。総トークン数は仮説 11.78 / 正解 11.73 とほぼ同じなので、
単純な「トークン数を減らしたがる」バイアスではなく、**機能語の接続を選択的に嫌う**バイアスである。

代表例（`ajimee-jwtd-v2-1800`, CER 0.06, コスト差 3.78）:

```
入力  にんむではかれからむせんでしじをうけて
正解  任務では彼から無線で指示を受けて
出力  任務では彼から無線で指示を受け手
      ...受け(verb,3.968) + て(particle,2.835) + 遷移 0.12 = 6.92
      ...受け手(noun,3.085)                                 = 3.09   ← こちらが勝つ
```

MeCab IPADIC の実コストで同じ対立を計算すると（`matrix.def` を直接引いた実測）:

```
を受けて   total=14401   を[w=4183,conn=-227] 受け[w=7436,conn=-1897] て[w=5170,conn=-308]
を受け手   total= 8538   を[w=4183,conn=-227] 受け手[w=5669,conn=-514]
```

**正直な注記**: この例では MeCab 自身も文脈なしでは「受け手」を選ぶ（8538 < 14401）。
つまりこのケースは接続コストだけでは解けず、前文脈が必要。事前観測の「て」系の誤りを
すべて接続コストのせいにするのは誤りである。

一方、接続コストだけで完全に説明できるケースもある（`ajimee-jwtd-v2-305`）:

```
入力  かたいからをもつたまごをうむこと、たかいたいしゃりつ
正解  硬い殻を持つ卵を産むこと、高い代謝率
出力  か大からを持つタマゴを有無コト、タカイ大車リツ

MeCab 実コスト:
  硬い殻   total= 7688   硬い[w=4748,conn=-2409] 殻[w=6556,conn=-634]
  か大から  total=22003   か[w=5360,conn=+1638] 大[w=6104,conn=+989] から[w=4159,conn=+2553]
```

MeCab は 14,315（BeME スケールで約 7.2）の差で「か大から」を棄却する。
その差は**すべて接続コストに入っている**（生起コスト合計は 11,304 対 15,623 で 4,319 差にすぎない）。
BeME は接続コストを持たないため、`か(0.4) 大(1.1) から(0.6)` = 2.1 が `硬い(2.624) 殻(3.528)` = 6.15 に勝ってしまう。

同じく `卵を産む`（5290）vs `タマゴを有無`（6446）も、差の主因は
格助詞→動詞の接続 −4,081 と格助詞→名詞の接続 −514 の差（3,567 ≒ BeME 1.78）である。

### 2.2 モデル誤り・同音／表記選択（60 件 / 30.0%、CER 寄与 27.1%）

分割は正しいが表層が違う類。CER 寄与は 27% だが、**IPADIC 由来の情報だけでは原理的に解けないものが多い**。

```
ajimee-jwtd-v2-1775  （音声が成るので注意）  正解 鳴る  コスト差 0.20
ajimee-jwtd-v2-2021  ...ユリを上げ           正解 挙げ  コスト差 0.82
ajimee-jwtd-v2-1011  の復しゅう              正解 復讐  コスト差 0.00（完全同点）
```

`復讐` の例は決定的である。辞書には 4 表記が**すべて同一コスト 2.484** で入っている:

```
ふくしゅう → 復しゅう(2.484) / 復習(2.484) / 復讎(2.484) / 復讐(2.484)
```

`converter.py:146` は `(cost, surface)` でソートするため、コードポイント順で `復しゅう` が勝つ。
これは BeME のコストマッピングの粗さではなく、**IPADIC 側で元々同点**（いずれも生起コスト 4467、
同一 left/right ID）である。実際 MeCab で計算しても `の復讐` = `の復習` = 7566 で完全同点。

同点率の実測: **曖昧な読み（2 表層以上を持つ読み）72,013 件のうち 21,592 件（30.0%）で
最小コストが同点**。うち 78% が 2 表記の同点。

**結論**: 表記選択は IPADIC の情報量では解決不能。Mozc がここで勝っているのは、
Mozc が形態素解析辞書ではなく**用例頻度で学習した変換用言語モデル + ユーザー学習**を持つからである。
BeME で埋めるならリランカ（Phase 2）か外部コーパス頻度が必要で、辞書拡充では動かない。

### 2.3 辞書欠落（25 件 / 12.5%、CER 寄与 13.5%）

必要パッチ数は 1 本が 19 件、2 本が 5 件、3 本が 1 件。合計 32 スパン。中身の実測:

```
まかおとじょまの → マカオとジョマの      すずきたかのりを → 鈴木尚典を
さぷりめんとの   → サプリメントの        とみのよしゆき   → 富野由悠季
はーぞぐかんとく → ハーゾグ監督          きょじんいでおん → 巨神イデオン
ひんさんびゃく   → 品３００              のくがつついたち → の９月１日
よがけ           → 夜駆け                らくさん         → 酪酸
```

三つに割れる。

1. **カタカナ固有名詞・外来語**（約半数）— IPADIC に無い人名・作品名・新しい外来語
2. **算用数字**（16 件の参照文字列が数字を含む）— AJIMEE は `３００`・`９月１日` を正解とするが、
   BeME に数詞→算用数字の変換経路が無い（辞書引きしかしないので `三〇〇` すら作れない）。
   これは辞書欠落というより**機能未実装**。
3. **真の語彙欠落**（`夜駆け`・`酪酸`・`銛撃ち砲` 等）— 数件のみ

事前観測の「歳差運動」は確かにここに属する（`さいさ` に対し `際さ(verb,3.777)` しか無い）。
一方で **「産卵」「復讐」は辞書に存在する**（`産卵` 2.462、`復讐` 2.484）。
事前仮説の「産卵・復讐が拾えない」は**誤り**で、これらは §2.1 / §2.2 のモデル誤りに分類される。

### 2.4 探索誤り（2 件 / 1.0%）— ビームは律速ではない

ビーム幅を変えた実測:

| 設定 | mean CER | 完全一致 |
|---|---:|---:|
| beam_width=64（既定） | 0.3414 | 6.0% |
| beam_width=256 | **0.3414** | 6.0% |

**完全に同一**。ビーム幅を 4 倍にしても 1 文字も変わらない。
探索に分類された 2 件（`復しゅう`/`復讐`、`伺える`/`窺える`）はいずれも**コスト完全同点**で、
`_path_key` のタイブレーク（表層のコードポイント順）に負けたもの。実質「探索誤り」は 0 件。

→ **ビーム幅・K-best の実装に手を入れても CER は動かない。**

### 2.5 リランカ（Phase 2）は AJIMEE で完全な no-op

`MockContextReranker` のキーワード表は `こうしょう` 系 6 表層しか持たない。
AJIMEE 200 件のうち、この 6 表層に触れるケースは **0 件**。
`scored_candidate_count=9499` はスコア関数を呼んだ回数であって、順位は 1 件も変わっていない。

したがって **CER 0.3414 は純粋な Phase 1 Viterbi の数値**であり、Phase 2 の寄与はゼロ。

さらにリランカの伸びしろ自体が小さい: **正解文字列が現在の 5-best 文候補に含まれるのは 200 件中 26 件（13.0%）**。
Cross-Encoder が完璧に働いても完全一致は 13% が上限。
**候補生成（Phase 1）を直さない限り Phase 2 に投資しても意味がない。**

## 3. 根本原因の特定（コード経路別）

### 3.1 `src/beme/lattice.py:160-191` — 接続コストの喪失（第一原因）

```python
_TRANSITION_COSTS = {
    ("noun", "particle"): 0.05,
    ("verb", "auxiliary"): 0.03,
    ...
}
# 未知の遷移: 同一 POS なら 0.08、それ以外 0.12
```

IPADIC の `matrix.def`（1316×1316、1,731,856 エントリ）の実測統計:

- 全体: min −16,124 / max +5,824 / 平均 −211 / 標準偏差 **1,542**
- 十分位: −2,110 / −1,416 / −926 / −510 / −115 / +296 / +659 / +1,079 / +1,702

現在のコストマッピング（§3.3）では **BeME 1.0 ≒ IPADIC 生コスト 2,000**。
BeME スケールに直すと接続コストは **標準偏差 0.77、レンジ −8.1〜+2.9** に相当する。
これに対し `_TRANSITION_COSTS` のレンジは **0.03〜0.20（幅 0.17）**。

BeME が固定値を置いている遷移について、IPADIC 実測値と並べる:

| 遷移 | IPADIC 中央値（生） | BeME 換算 | **BeME 固定値** | 誤差 |
|---|---:|---:|---:|---:|
| 名詞一般 → 格助詞 | **−4,646** | −2.32 | +0.05 | **+2.37** |
| 固有名詞 → 格助詞 | −3,743 | −1.87 | +0.05 | +1.92 |
| 名詞サ変接続 → スル | −3,776 | −1.89 | —（+0.12） | +2.01 |
| 名詞一般 → 名詞接尾 | −3,005 | −1.50 | —（+0.12） | **+1.62** |
| 動詞連用形 → 接続助詞（て/で） | −2,562 | −1.28 | +0.05 | +1.33 |
| 動詞連用形 → 助動詞 | −1,996 | −1.00 | +0.03 | +1.03 |
| 名詞一般 → 名詞一般 | +62 | +0.03 | +0.08 | +0.05 |
| 名詞一般 → 動詞自立 | +217 | +0.11 | +0.12 | +0.01 |

**符号が逆転している。** IPADIC は「名詞に格助詞が付く」「動詞連用形に助動詞が付く」といった
自然な接続を **1.0〜2.3 BeME 単位の報酬**で強く推す。BeME は同じ接続に **0.03〜0.12 の罰**を課す。
1 境界あたり 1.0〜2.4 単位の誤差が生じ、これが §2.1 の「接尾辞 1/44・助動詞 1/6.7」という
品詞分布の歪みを直接生む。

**定量的整合性の確認**: 1 文あたり約 11 トークン、うち機能語接続がおよそ 1/3 とすると
累積誤差は 3.7〜8.8 単位。実測されたオラクルとの**コスト差の中央値 2.75・平均 3.73**
（四分位 1.17 / 2.75 / 5.21）とオーダーが一致する。**観測されたコスト差は
接続コスト欠落だけでほぼ説明がつく。**

### 3.2 `src/beme/ipadic.py:55-82` — POS 粒度の情報損失（第二原因、かつ 3.1 の修復を阻む要因）

`map_ipadic_pos` は IPADIC の品詞階層を 16 ラベルに畳む。
`matrix.def` の全 1,731,856 エントリを「BeME POS ペア」（289 グループ）で群別化し、分散分解した実測:

```
BeME POS ラベルへ潰したときの説明分散  R^2 = 0.2097
群内残差標準偏差                       1,371 生コスト（≒ 0.69 BeME 単位）
全体標準偏差                           1,542 生コスト
```

**接続コストの分散の 79% は BeME の POS ラベルでは区別できない位置にある。**
同じ「verb → particle」の中でも十分位範囲は −2,361〜+1,076（幅 3,437 ≒ 1.7 BeME 単位）に散らばる。
判別信号は活用形レベル（`動詞,自立,*,*,五段・ラ行,連用形` 等）に載っているのに、
`map_ipadic_pos` はそこを捨てている。

**帰結**: 16×16 の POS 遷移表をどれだけ丁寧にチューニングしても、
接続コスト信号の 21% しか回収できない。これは §5 の実測（POS 表に報酬を入れても
CER 0.3414 → 0.3398 とほぼ動かない）と一致する。

### 3.3 `src/beme/ipadic.py:85-106` — コストマッピングの評価

```python
bounded = min(max(raw_cost, 3000), 10000)
ratio = (bounded - 3000) / 7000
return round(1.75 + ratio * 3.50, 3)
```

**この式自体は思ったほど悪くない。** 実測:

- IPADIC 生起コスト 392,126 行の分布: min −6,716 / max 19,888 / 中央値 7,250 / p5 4,465 / p95 9,279
- クリップされるのは下端 1,294 行（0.33%）・上端 2,674 行（0.68%）の計 **1.01%** のみ
- 写像は単調線形なので **99% のエントリについて生起コストの順序は保存されている**
- 出力辞書での床値 1.750 は 0.33%、天井値 5.250 は 0.51%

したがって「コストマッピングが粗いことが CER の主因」という事前仮説は**支持されない**。
ただし三つの実害がある。

1. **上端クリップが効く場所が悪い**: 生コスト 19,888 の語も 10,000 の語も同じ 5.25 になる。
   9,888 生コスト（≒ 4.9 BeME 単位）の罰が消える。該当する 2,674 件は
   まさに「めったに出ない長い固有名詞」であり、最長一致バイアスで拾われやすい層と重なる。
2. **スケールの取り決めが暗黙**: 1 BeME = 2,000 生コストという換算が
   どこにも明示されず、`_TRANSITION_COSTS` が別スケールで手書きされている。
   §3.1 の不整合はここから生じている。
3. **手作り overlay とのスケール衝突**（§3.4）。

### 3.4 `data/dictionary_manual.tsv` と床値 1.75 — 意図的だが両刃

`map_ipadic_cost` の docstring は床値の意図を明記している:

> "The default BeME floor deliberately remains above every hand-maintained overlay cost
> so the established homophone priorities win exact-reading ties."

実測: overlay 133 件のコストは **0.35〜1.65** で、全件が IPADIC 床値 1.75 を下回る。
うち 66 件が 1 文字表層（`橋 0.80`・`公 1.20`・`車 1.20`・`人 0.75`・`教会 0.75` 等）。

これは手作り 12 件の回帰セットには最適だが、文レベルでは**強力なアトラクタ**になる。
`ajimee-jwtd-v2-1992` の出力 `会テンジクが触れまわるよウニウゴ臭いサウンドウノコト` の
`会(1.1)`、`ajimee-jwtd-v2-305` の `大(1.1) 車(1.2)`、`ajimee-jwtd-v2-14` の `公(1.2)` は
すべて overlay 由来の 1 文字語である。

**ただし実測は単純ではない**（重要）:

| 設定 | mean CER |
|---|---:|
| baseline | 0.3414 |
| **overlay を外す（IPADIC のみ）** | **0.4653（大幅悪化）** |

overlay を外すと `を`・`の`・`が` などの助詞が IPADIC コスト（2.5〜5.0 相当）に戻り、
モデルが助詞を立てなくなって崩壊する。
**つまり overlay の 17 個の格助詞（0.35〜0.60）は、欠落している
「名詞→格助詞 −2.3」の接続報酬を、生起コスト側で肩代わりしている手当てである。**

overlay は「バグ」ではなく「§3.1 の欠陥に対する手作業のパッチ」。
接続コストを正しく入れれば不要になるが、**接続コストを入れる前に外すと悪化する**。
片方だけ触ると壊れる依存関係がある。

### 3.5 `src/beme/dictionary.py` — 辞書の性格のミスマッチ（見落とされている構造的問題）

IPADIC は**形態素解析用**の辞書であり、**IME の変換用辞書ではない**。
解析器はカタカナ表記の入力テキストを読むためにカタカナ表層のエントリを必要とするが、
IME ではそれが**生成候補**として湧いてくる。実測:

- カタカナ表層のエントリ: **17,293 / 349,043 = 5.0%**
- 曖昧な読み 72,013 件のうち、**最安表層がカタカナなのは 4,071 件（5.7%）**
- 表層が読み（ひらがな）と同一のエントリ: **59,518 件**（`はなしは` のような無変換出力を生む）

出力への漏れ出しの実測:

```
仮説のカタカナ文字比率        834/4379 = 19.05%
正解のカタカナ文字比率        485/4245 = 11.43%
正解よりカタカナが多いケース  106/200  = 53%
```

これが「テンジク」「ウニ」「ウゴ」「タマゴ」「タカイ」「コト」の正体である。
実際 `こと(noun, 2.978)` より `コト(noun, 2.455)` のほうが安い。

**正直な注記**: `てんじく` は MeCab で計算しても `テンジク`(2801) が `天竺`(5065) に勝つ。
これは BeME のマッピングの問題ではなく、**IPADIC を IME 辞書として使うことに内在する問題**。
Mozc が同じ失敗をしないのは、Mozc の変換辞書が用例頻度ベースで別物だからである。

### 3.6 その他のコード経路（CER への寄与は小さいが記録）

- `src/beme/converter.py:148-151` — `confidence` はリランク前候補から計算され、
  `needs_rerank` は `benchmark.convert_sentence` に一切参照されない。
  文レベルではカスケード判定は**表示専用**になっている。
- `src/beme/benchmark.py:128-146` — スパンごとに Viterbi を独立に走らせ、
  各スパン先頭で直前 POS が None にリセットされる。句読点をまたぐ接続がモデル化されない。
  さらに合成時に `k=5` で打ち切るため、長文では前半の誤りが後半に伝播する。
- `src/beme/benchmark.py:65-79` — `katakana_to_hiragana` が入力のカタカナを潰すため、
  `サプリメント` のように「入力がカタカナで正解もカタカナ」の語を辞書経由で復元する必要が生じる。
  §2.3 の欠落の一部はこれ由来（ただし AJIMEE の入力形式上、避けにくい）。

## 4. コストマッピングの評価と改善案（`src/beme/ipadic.py`）

### 4.1 現設計の問題点（優先度順）

| # | 問題 | 根拠 | 深刻度 |
|---|---|---|---|
| 1 | 接続コスト（matrix.def）を取り込まず、16×16 の手書き表に置換 | §3.1 実測。符号が逆で桁が 1〜2 桁小さい | **致命的** |
| 2 | `map_ipadic_pos` が left/right ID を捨てるため、接続コストを後から入れる道も塞いでいる | §3.2 R²=0.21 | **致命的** |
| 3 | IPADIC を IME 変換辞書として無加工で使用（カタカナ・ひらがな表層が候補化） | §3.5、カタカナ 5.0%、出力漏れ 53% | **大** |
| 4 | 上端クリップ 10,000 が希少長語の罰を消す | §3.3、2,674 件 | 中 |
| 5 | overlay と IPADIC のコストスケールが非連続（0.35〜1.65 vs 1.75〜5.25） | §3.4 | 中（ただし現状は補償として機能） |
| 6 | 「1 BeME 単位 = 2,000 生コスト」の換算がコード上に明示されない | §3.3 | 中（設計上の負債） |

### 4.2 改善案

**案 A（本命）: IPADIC の ID と matrix.def をそのまま持ち込む**

辞書 TSV に `left_id` / `right_id` を追加し、`matrix.def` をバイナリで同梱、
`pos_transition_cost` を `matrix[right_id_prev][left_id_cur]` の参照に置き換える。

- 生起コストのスケーリングも不要（生コストのまま加算すれば MeCab と同一の目的関数になる）
- `_TRANSITION_COSTS` は削除。`map_ipadic_pos` は表示・リランカ用に残す
- サイズ: matrix.def は 1316² × 2 バイト = **約 3.4 MB**（int16 で足りる。実測レンジ −16,124〜+5,824）。
  現行 `data/dictionary.tsv` が 14.6 MB なので追加負担は小さい
- overlay は「生コスト側のバイアス」として `raw_cost - Δ` の形に書き直す必要がある（§3.4 の依存関係）

**案 B（案 A に進めない場合の次善）: 品詞細分類レベルの遷移表**

`map_ipadic_pos` を活用形・品詞細分類まで含む 100〜300 ラベルに拡張し、
遷移コストを matrix.def から**群平均で学習**（コードに手書きしない）。
R² は 0.21 から改善するが上限は不明（未測定 — 実装前に同じ分散分解で見積もるべき）。

**案 C（コストマッピング自体の微修正、案 A と独立に有効）**

1. 上端クリップを 10,000 → 15,000 に緩める（p99.3 をカバー）か、上端側だけ対数圧縮にする。
   希少長語の罰が戻る
2. 変換係数 `BEME_UNITS_PER_RAW_COST = 1/2000` を定数として明示し、
   遷移コスト・overlay コストを同じ単位で書けるようにする
3. カタカナ表層・ひらがな表層（`surface == reading`）のエントリにビルド時ペナルティを加える
   （実測効果は §5）

## 9. 不確かな点・未検証の事項

- **P1（matrix.def 取り込み）の CER 期待値 0.15〜0.22 は見積もりであり実測ではない。**
  §2.1 の個別事例で MeCab が正しい側を選べることは確認したが、200 件全体で
  どこまで改善するかは実装しないと分からない。最初の一歩として
  「BeME の 1-best と、MeCab コストで再スコアした 1-best を比較する」オフライン実験を
  実装前に走らせれば、低コストで上限を確かめられる。
- **カタカナペナルティの最適値 +1.0 は AJIMEE 200 件でのチューニング結果**であり、
  過適合の疑いがある。Mozc 498 件でも同じ値が最適かは未検証。
- **オラクル DP のパッチ辺は読み 8 文字・表層 8 文字が上限**。これを超える長い未知語は
  複数パッチに分解されるため、「辞書欠落 25 件」はやや過大側に振れている可能性がある。
- **Mozc スイートの失敗分解（オラクル DP）は未実施**。§7 は集計と目視サンプルのみ。
- **`convert_sentence` のスパン合成（k=5 打ち切り）が CER に与える影響は単独で測っていない。**
  §2.4 のビーム実験は各スパン内の探索のみを広げており、スパン間の打ち切りは変えていない。
- **`beam_width=1024` は実行時間の都合で完走させていない**（256 で変化ゼロだったため打ち切り）。
